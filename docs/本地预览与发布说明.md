# 本地预览与发布说明

本文说明如何实时查看正在编写的 Jekyll 网页，以及调试完成后如何让修改正式生效。

## 一、准备工作

在项目根目录打开 VS Code 终端，确认当前目录是本项目目录：

```powershell
cd D:\git\DesenbergChina.github.io
```

第一次运行项目，或修改了 `Gemfile` 后，先安装依赖：

```powershell
bundle install
```

如果电脑尚未安装 Bundler，可以先执行：

```powershell
gem install bundler
```

## 二、启动本地网站

在项目根目录执行：

```powershell
bundle exec jekyll serve --livereload
```

看到类似下面的提示后，说明本地服务已经启动：

```text
Server address: http://127.0.0.1:4000/
Server running...
```

然后在浏览器中打开：

<http://localhost:4000/>

也可以使用：

<http://127.0.0.1:4000/>

不要直接双击 `_site` 目录中的 HTML 文件。通过 Jekyll 服务访问，才能正确处理 Markdown、Liquid 模板、站点配置和资源路径。

## 三、实时查看修改效果

保持 `bundle exec jekyll serve --livereload` 命令持续运行，然后在 VS Code 中编辑并保存文件：

- 修改文章：保存 `_posts/` 下的 Markdown 文件；
- 修改页面：保存根目录页面或 `_pages/` 下的 Markdown 文件；
- 修改导航：保存 `_data/navigation.yml`；
- 修改样式和脚本：保存 `assets/` 下对应的 CSS 或 JavaScript 文件。

保存后，Jekyll 会自动重新构建网页，浏览器通常会自动刷新。若浏览器没有刷新，可以手动按 `Ctrl + R`，或确认终端是否出现构建错误。

### 需要重启服务的情况

修改 `_config.yml`、`Gemfile` 或插件配置后，需要在终端按 `Ctrl + C` 停止服务，再重新启动：

```powershell
bundle exec jekyll serve --livereload
```

这是因为 `_config.yml` 的配置不会被当前 Jekyll 进程自动重新加载。

## 四、调试时重点检查

在浏览器中依次检查：

1. 首页是否能正常打开；
2. 顶部导航链接是否能跳转；
3. 文章标题、日期、分类和标签是否正确；
4. 图片、CSS 和 JavaScript 是否正常加载；
5. 浏览器开发者工具的 Console 中是否有报错；
6. 浏览器开发者工具的 Network 中是否存在 404 资源；
7. 手机或窄窗口下是否出现横向滚动和内容溢出。

如果页面没有更新，可以依次确认：

- 文件是否已经保存；
- 终端中的 Jekyll 服务是否仍在运行；
- 终端是否显示 Liquid、YAML 或 Markdown 错误；
- 是否修改了需要重启服务的 `_config.yml`；
- 是否需要清理缓存后重新构建。

清理 Jekyll 缓存后重新启动：

```powershell
bundle exec jekyll clean
bundle exec jekyll serve --livereload
```

## 五、发布前构建检查

确认本地页面没有问题后，先停止实时预览服务，执行生产构建：

```powershell
bundle exec jekyll build
```

构建成功时，终端会显示类似：

```text
Site build: _site
```

这一步可以提前发现 YAML、Liquid、Markdown、链接和资源路径等构建问题。构建失败时，先根据终端显示的文件路径和行号修复错误，再重新执行构建。

`_site/` 是 Jekyll 自动生成的发布文件夹，通常不需要手动编辑其中的文件。应当修改源文件，然后重新构建。

## 六、让修改在线上生效

本地构建成功后，在项目根目录执行：

```powershell
git status
git add .
git commit -m "更新网站内容"
git push origin main
```

推送成功后，GitHub Pages 会自动读取 `main` 分支的最新代码并重新构建网站。通常需要等待一段时间，线上页面才会更新。

可以在 GitHub 仓库的 **Actions** 页面查看构建状态：

- 构建成功：打开网站并刷新页面；
- 构建失败：打开失败的工作流，查看日志中的错误文件和行号；
- 页面仍显示旧内容：等待部署完成后，使用 `Ctrl + F5` 强制刷新浏览器缓存。

如果仓库使用的是从分支部署，需要在 GitHub 仓库的 **Settings → Pages** 中确认：

- Source 设置为 `Deploy from a branch`；
- Branch 设置为 `main`；
- 目录设置为 `/(root)`。

## 七、推荐的日常工作流程

```text
编辑源文件
   ↓
保存文件
   ↓
访问 http://localhost:4000/ 实时查看
   ↓
修复页面、样式或构建错误
   ↓
bundle exec jekyll build
   ↓
git add .
   ↓
git commit -m "更新网站内容"
   ↓
git push origin main
   ↓
等待 GitHub Pages 部署完成
```

以后每次修改网站内容，都按照这个流程操作即可：本地预览用于调试，`jekyll build` 用于发布前检查，`git push` 用于让线上网站更新。
