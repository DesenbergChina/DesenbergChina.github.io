## 前言

Codex CLI 用久以后，最容易忘的往往不是“怎么启动”，而是：

- 我之前有哪些会话？
- 怎么继续最近一次会话？
- 怎么查看其他项目里的历史会话？
- `resume` 和 `fork` 有什么区别？
- 怎么让 Codex 执行一次任务后直接退出？
- 怎么快速检查版本、更新和运行环境？

这篇文章把我日常最常用的 Codex CLI 指令整理成一份速查表。

> 本文按 **2026-09-18** 的 Codex CLI 命令结构整理。Codex CLI 更新较快，如果某条命令在你的版本中不可用，优先运行 `codex --help` 或对应子命令的 `--help` 查看本机版本实际支持的参数。

---

## 1. 最常用的 8 条命令

如果只想先记住最核心的一组，可以记下面这些：

```powershell
# 启动 Codex CLI
codex

# 查看帮助
codex --help

# 查看当前版本
codex --version

# 查看 / 恢复当前项目的历史会话
codex resume

# 查看所有项目的历史会话
codex resume --all

# 直接恢复最近一次会话
codex resume --last

# 从历史会话创建一个新的分支会话
codex fork

# 检查 Codex 安装、配置、认证和运行环境
codex doctor
```

其中最值得记住的是：

```powershell
codex resume --all
```

当你想回答“**我以前有哪些 Codex 会话？**”时，这通常是最直接的命令。

## 2. 启动 Codex

最普通的启动方式：

```powershell
codex
```

进入交互式 TUI 后，就可以直接输入任务，例如：

```text
帮我分析一下这个项目的目录结构
```

也可以在启动时直接带上第一条提示：

```powershell
codex "分析当前项目并告诉我入口文件在哪里"
```

如果想确认当前 Codex CLI 版本：

```powershell
codex --version
```

查看当前版本支持的完整命令：

```powershell
codex --help
```

对于变化较快的 CLI 工具，`--help` 往往比网上旧教程更可靠。

## 3. 查看和恢复历史会话：`codex resume`

### 3.1 查看当前项目的历史会话

在项目目录中执行：

```powershell
codex resume
```

Codex 会打开一个历史会话选择器。

默认情况下，会话列表会按照**当前工作目录（CWD）**进行过滤，因此更适合查找当前项目以前的聊天。

---

### 3.2 查看所有项目的历史会话

如果你在多个项目中使用 Codex，只执行 `codex resume` 可能看不到其他目录中的会话。

这时使用：

```powershell
codex resume --all
```

`--all` 会取消当前工作目录过滤，并在选择器中显示会话对应的 CWD。

因此我最常使用的是：

```text
不知道以前在哪个项目聊过
        ↓
codex resume --all
        ↓
查看所有本地会话
        ↓
选择目标会话
        ↓
Enter 恢复
```

---

### 3.3 直接继续最近一次会话

如果确定只需要最近一次会话：

```powershell
codex resume --last
```

这样不会打开选择器，而是直接继续最近记录的会话。

---

### 3.4 按会话 ID 或名称恢复

也可以直接指定会话：

```powershell
codex resume <SESSION_ID>
```

例如：

```powershell
codex resume 019xxxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

当前 Codex CLI 也支持按会话名称查找；如果输入可以解析为 UUID，则 UUID 优先。

---

### 3.5 查看非交互式会话

`codex exec` 创建的非交互式运行默认不会全部混在普通交互会话选择器里。

需要时可以使用：

```powershell
codex resume --all --include-non-interactive
```

这个参数更适合排查自动化任务或恢复之前的 `codex exec` 上下文。

## 4. `resume` 和 `fork` 的区别

这两个命令看起来很像，但用途不同。

### `resume`：继续原会话

```powershell
codex resume
```

逻辑可以理解为：

```text
原会话 ──────────────────→ 继续原会话
                            上下文继续累积
```

适合：

- 同一个 Bug 继续修；
- 同一个功能继续开发；
- 上次任务还没结束；
- 希望保留同一条聊天历史。

---

### `fork`：从旧会话分出新路线

```powershell
codex fork
```

可以理解为：

```text
原会话 ──────┬──────────→ 原会话
             │
             └──────────→ 新分支会话
                           继承此前上下文
```

适合：

- 想保留原方案，同时尝试另一个实现；
- 从某个历史节点探索不同修改路径；
- 做 A/B 方案比较；
- 不想污染原来的会话。

常用方式：

```powershell
# 从选择器中选择一个会话创建分支
codex fork

# 从最近一次会话创建分支
codex fork --last

# 从所有项目的历史会话中选择
codex fork --all

# 从指定会话创建分支
codex fork <SESSION_ID>
```

简单记忆：

> **继续同一件事用 `resume`，从旧上下文尝试另一条路线用 `fork`。**

## 5. 非交互执行：`codex exec`

平时运行：

```powershell
codex
```

会进入交互式界面。

如果只想让 Codex 执行一个任务，完成后返回 Shell，可以使用：

```powershell
codex exec "检查当前项目有没有明显的 Bug"
```

这种方式适合：

- PowerShell / Bash 脚本；
- CI；
- 批处理；
- 一次性代码分析；
- 自动化工作流。

例如：

```powershell
codex exec "检查当前未提交修改中的潜在问题"
```

---

### 恢复上一次非交互任务

Codex 官方支持继续之前的 `exec` 会话：

```powershell
codex exec resume --last "继续修复刚才发现的问题"
```

或者指定会话：

```powershell
codex exec resume <SESSION_ID> "继续完成剩余任务"
```

这种方式很适合两阶段自动化：

```powershell
codex exec "检查代码中的并发问题"
codex exec resume --last "修复刚才发现的并发问题"
```

## 6. 代码审查：`codex review`

Codex CLI 可以直接执行代码审查：

```powershell
codex review
```

在交互式 Codex 中也可以使用：

```text
/review
```

常见用途包括：

- 审查未提交修改；
- 对照基准分支检查改动；
- 审查某个提交；
- 在提交或创建 Pull Request 前查找潜在问题。

代码审查模式的重点是**检查问题**，而不是直接修改工作树，因此很适合放在 Git 提交之前。

## 7. 更新与环境诊断

### 查看版本

```powershell
codex --version
```

---

### 更新 Codex

当前 Codex CLI 提供：

```powershell
codex update
```

升级后建议再次确认：

```powershell
codex --version
```

---

### 运行环境诊断

如果遇到登录、配置、安装或运行环境异常：

```powershell
codex doctor
```

该命令主要检查：

- Codex 安装；
- 配置；
- 登录 / 认证；
- Runtime 健康状态。

因此遇到莫名其妙的 CLI 问题时，可以先执行：

```powershell
codex doctor
```

## 10. 会话归档和删除

新版 Codex CLI 还提供了更完整的本地会话管理。

归档会话：

```powershell
codex archive <SESSION_ID或名称>
```

取消归档：

```powershell
codex unarchive <SESSION_ID或名称>
```

永久删除：

```powershell
codex delete <SESSION_ID或名称>
```

这里需要特别注意：

> `archive` 更像“隐藏 / 收纳”，而 `delete` 是永久删除。普通整理优先使用归档，不要把删除当作归档使用。

## 12. 进入 Codex 后常用的 Slash Commands

需要区分两套命令。

下面这些：

```powershell
codex resume --all
codex doctor
codex exec "..."
```

是在 **PowerShell / Bash** 中运行的 CLI 命令。

而进入：

```powershell
codex
```

之后输入的：

```text
/init
/status
/permissions
/model
/review
```

属于 Codex TUI 内部的 **Slash Commands**。

最常用的几个：

| Slash Command | 作用 |
|---|---|
| `/init` | 创建 `AGENTS.md`，为项目设置 Codex 指令 |
| `/status` | 查看当前会话配置 |
| `/permissions` | 设置 Codex 允许执行的操作 |
| `/model` | 选择模型与 reasoning effort |
| `/review` | 对当前代码改动执行代码审查 |

因此可以简单理解成：

```text
PowerShell / Bash
    │
    ├─ codex resume
    ├─ codex fork
    ├─ codex exec
    ├─ codex doctor
    └─ codex update

进入 codex TUI 后
    │
    ├─ /status
    ├─ /model
    ├─ /permissions
    ├─ /review
    └─ /init
```


---
