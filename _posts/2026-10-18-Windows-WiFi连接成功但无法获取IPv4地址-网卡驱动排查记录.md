## 故障现象

一台 Windows 电脑连接家中的主 Wi-Fi 后，系统显示“已连接”，但提示没有网络。查看网络状态时，无线网卡没有取得可用的 IPv4 地址和默认网关。有时会看到 `169.254.x.x`：这是 Windows 在未取得 DHCP 地址时可能使用的本地地址，不能据此访问正常的家庭网络。

为保护隐私，下文把主网络称为 **Wi-Fi A**，把访客网络称为 **Wi-Fi B**。实际的网络名称、设备型号、MAC 地址、内网地址和日志时间均不公开。

当时的对照结果是：

| 测试 | 结果 |
|---|---|
| 这台电脑连接 Wi-Fi A | 无法正常获取 IPv4 地址，不能上网 |
| 这台电脑连接 Wi-Fi B | 可以获取地址并上网 |
| 另一台设备连接 Wi-Fi A | 可以正常上网 |

因此，不能仅凭“已连接”判断网络可用；还要检查 IP 地址、默认网关和实际连通性。

## 排查经过

此前曾在路由器上设置固定 IP 与设备绑定。故障出现后，已撤销该绑定，确认路由器的 DHCP（自动分配 IP 地址）服务开启，并把电脑的 IPv4 设置恢复为自动获取。忘记网络后重连、重启网卡以及重启设备，也没有让 Wi-Fi A 恢复。

接着查看 Windows 事件查看器中的“系统”和“WLAN-AutoConfig/Operational”日志，发现了先后顺序：

1. Windows 先记录了连接 Wi-Fi A 成功，包括无线关联和安全认证成功。
2. 十几秒后，无线网卡驱动反复记录事件 **5002** 和 **5005**，提示适配器运行异常及内部错误。
3. 之后，DHCP 客户端才记录获取地址失败。

同时，Wi-Fi B 在同一台电脑上可以正常使用。两次连接都曾使用 WPA3 和 Wi-Fi 6，因此不能只凭这些协议名称认定故障原因。另一台设备能使用 Wi-Fi A，也说明主网络并非全面中断。

这些记录将排查重点指向**这台电脑的无线网卡驱动及其与 Wi-Fi A 的交互**。路由器没有后续日志，本身不能证明故障一定在电脑；真正有价值的是电脑端驱动报错早于 DHCP 失败。

> 事件 5002、5005 是定位线索，不是硬件损坏的诊断书。仅靠事件编号，无法区分驱动文件、固件、网络状态或硬件问题。

## 实际有效的处理

在本次案例中，我从[英特尔官方无线驱动下载页](https://www.intel.com/content/www/us/en/download/19351/intel-wireless-wi-fi-drivers-for-windows-10-and-windows-11.html)下载并安装了适配这台电脑无线网卡的驱动，版本为 **24.70.0.3**。

随后重新连接 Wi-Fi A，电脑恢复了正常连接和上网。**这次已验证的结果是：安装 24.70.0.3 后，原故障消失。** 这说明驱动更新对本次故障有效，但无法仅凭这一结果断定旧驱动的具体缺陷，或排除原有驱动状态受损等因素。

如果你遇到类似现象，可以按以下顺序操作：

1. 在设备管理器确认无线网卡型号及当前驱动版本。
2. 从电脑厂商或网卡厂商的**官方网站**下载与网卡、Windows 版本匹配的驱动，并先把安装包保存到本地。
3. 安装驱动，必要时按安装程序提示重启电脑。
4. 重新连接出现故障的 Wi-Fi，确认获得可用的 IPv4 地址和默认网关，并实际打开网页测试。

下载前先确认型号。不要因为别人的案例使用了 24.70.0.3，就直接给不同型号的网卡安装同一个驱动。如果普通安装仍无效，可再参考[英特尔的无线驱动清洁安装指南](https://www.intel.com/content/www/us/en/support/articles/000022173/wireless.html)。清洁安装可能暂时移除无线连接，因此要先保存安装包。本次案例只确认了重新安装新版驱动有效，**没有把清洁安装作为已经执行的步骤**。

## 两个容易误判的地方

**第一，`169.254.x.x` 不是 DNS 问题的证据。** 若电脑尚未取得正常的 IPv4 地址和默认网关，优先检查无线连接与 DHCP 链路。此时单独修改 DNS，通常不能解决当前的取址故障。

**第二，驱动“回退”不一定保持生效。** 本次安装记录显示，电脑在回退驱动后又自动安装了已有的驱动版本。因此，判断某个版本是否有效，应在测试时核对设备管理器实际显示的版本，不要只依据曾经点击过“回退驱动”。

## 小结

这次故障的关键证据是：主 Wi-Fi 认证成功后，无线网卡驱动先连续报错，DHCP 随后取址失败；访客网络和另一台设备则能上网。安装适配的 **24.70.0.3** 驱动后，主 Wi-Fi 恢复正常。

遇到“Wi-Fi 已连接但没有 IPv4 地址”时，先用对照测试和事件日志确定故障出现在哪一层，再处理对应的驱动或配置。不要把“已连接”等同于“已经取得可用网络”。
